## 推荐第一项实现任务：单 Screen 的 JSON 编辑闭环

目标：用户从面板放入 Button、EditBox、StringWidget 和矩形；拖动/精确输入位置尺寸；导出 JSON 后重新导入恢复同一设计。先不加入积木、背包、资源抓取、原版皮肤或 Java 输出。

实施顺序：

1. 固定兼容的 Node/包管理器及 React、TS、Vite、Konva/react-konva、Zustand、Zod、Vitest、Playwright 版本，创建最小静态应用。
2. 实现四种类型的领域模型、组件目录、校验与 JSON 往返；先固定一个 Screen，坐标整数、居中参考设计区，严格拒绝错误来源及悬空引用。
3. 接入 Konva，验证拖入、单选、拖动、尺寸调整及 DOM 属性表单；自然尺寸组件暂不加入。
4. 加入一次手势一条记录的撤销/重做；取消拖动不留下历史，导入是一次可撤销事务。
5. 文件下载/导入与最小 E2E 收尾。若 Konva 在坐标、文字或交互目标上不能通过门槛，记录失败再决定 DOM/SVG 替代，不并行维护两套引擎。

验收：在 0.5×、1×、2× zoom、有 pan、DPR 1/2 的浏览器环境中，添加/移动/调整/撤销/重做后 JSON 为整数且位置正确；导出再导入语义一致；空/损坏/未来版本 JSON 不破坏当前项目。构建和 typecheck 成功，Vitest 领域测试通过，Playwright 至少一个四组件端到端往返通过。性能采样为 300 个简单节点记录拖动帧时间，基于实测决定是否需要优化，不在现在承诺硬件无关 FPS。

## 后续模块

| 阶段/模块 | 依赖 | 验证方式 | 主要风险与范围 |
|---|---|---|---|
| A 领域模型/目录/校验 | 本次 Schema 与审计 | Vitest：合法/非法类型、尺寸、ID/引用、source 一致、导入失败保持原文档 | 目录错误会污染所有输出；原生分类只能由证据确定 |
| B 画布与属性/历史 | A | Playwright：坐标矩阵、键盘微调、边界和手势撤销；纯函数测几何 | Konva scale 污染、焦点/IME、设计模式误触发行为；这是第一任务的主闭环 |
| C 本地持久化 | A+B | 实际 IndexedDB：刷新、版本升级、配额失败、保存乱序、多标签页冲突 | 本地浏览器清理不可恢复；提供 JSON 备份入口，保存失败不能显示已保存 |
| D 参考 PNG 与实现 Prompt | A+B；资源包依赖 E | PNG 尺寸与无选择框；Prompt 快照覆盖版本、坐标、类别、限制、缺资源与服务端责任 | 浏览器皮肤近似、文字度量与游戏差异；所有输出来自同一文档 revision |
| E 图片/资源引用与 ZIP | C+D | 往返用户 PNG、缺失资源占位、hash、ZIP 路径和解压限额负例 | 资产许可、Canvas 污染、压缩炸弹；不内置游戏分发资产，只接收合法用户 PNG |
| F 受限交互规格表单与预览 | A+B，冻结 AST 合同 | 表单→AST往返；类型错误、分支上限、变量更新、初值恢复与无循环触发 | 浏览器模拟不能证明 Java API 回调或服务端安全；预览运行在副本 |
| G Blockly 适配 | F | AST→积木→AST等价、未知 op 拒绝、积木删除/撤销与引用一致 | Blockly 序列化锁死项目格式、双历史系统冲突；一次积木事务只写一次领域历史 |
| H 扩展目录 | A+D+相关交互/资产模块 | 对每种组件做源码合同检查与相应预览测试 | Checkbox 自然尺寸、CycleButton语义、Slider需实现钩子、列表/槽位不是独立 Widget；逐个加入 |

最小可用规格编辑器闭环为 A+B+C+D；用户完整描述中的“拖放+积木+完整资源交付”需要继续完成 E/F/G。不能把完成 A+B 宣称整个 V1 完成，也不要求在 A+B 前就实现后续系统。
