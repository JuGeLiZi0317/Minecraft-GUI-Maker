# D-Export 文件名与 ZIP 合同 0.3.1

> 文件名中的批次短码已被用户要求移除；现行文件名与 F0 导出合同见 [F0 行为规格](F0_BEHAVIOR_CONTRACT.md)。本页保留 0.3.1 历史。

本修订替代旧导出合同中仅以 `gui-r...` 命名及不提供 ZIP 的条款，保留单快照、原始 JSON 权威、草稿提交、引用与 PNG 语义。领域 Schema 不变。批次的设计名称来自已提交快照 `project.name`；文件名清理不会改变文档。规格与 manifest 的文件引用使用本批实际名称；exportId、revision、摘要仍是关联标识，并非从名称推断身份。

集中命名保留 Unicode，将 Windows 禁止字符、路径分隔符和控制字符替换为下划线，移除首尾空白及末尾句点，防止设备名，并将前缀限制为 120 个 UTF-8 字节。清理后为空或全句点使用 `minecraft-gui`。每个批次追加 `-r<revision>-<exportId前8位>`，再依次使用 `.project.json`、`.design.png`、`.reference.png`、`.implementation.json`、`.prompt.md`、`.manifest.json`，Panel 启用时另有 `.background.png`；ZIP 使用 `.zip`。独立 JSON 快捷下载使用 `<名称>.project.json`。损坏记录的恢复下载只能从可解析记录读取名称，否则使用固定后备名称，后缀 `.recovery-record.json`；恢复记录不是权威设计导出。

顶部「导出 ZIP」一次提交草稿、捕获快照、生成并下载 ZIP，同时保留同批单文件入口；也可先生成导出批次，再在结果面板选择逐项下载或「导出 ZIP」。ZIP 原样包含同批全部文件，包括 manifest；manifest 列出其他所有文件的名称、长度和摘要，自身不计算递归摘要。每个条目是平铺的 UTF-8 安全文件名，重名和路径分隔符被拒绝。没有原始客户端 JAR、完整资源包或字体源文件。使用不压缩的 ZIP 条目，避免重复编码和压缩内存不可预期。

条目数据合计上限 64 MiB，超过即拒绝打包；加上 ZIP 本地头、目录和文件名的有限元数据。预算按最多 64 MiB 既有文件数据、64 MiB 为 ZIP 复制数据以及最多约 64 MiB 的 ZIP Blob 副本估算；浏览器可能另外保留已有单文件 Blob、渲染画布或自身开销，因此不是整个浏览器进程的硬内存上限。计算 CRC 时分块让出主线程并检查资源、字体代次。打包前或打包中发生变化则拒绝完整 ZIP，不创建下载；用户可重新生成批次。导出打包不修改文档、历史或存储；生成批次前仍按原合同验证并提交未完成的有效草稿。

非 Panel 项目不包含背景文件，Panel 项目按现有导出合同生成并在 manifest 中列出。游戏视觉、浏览器兼容、资源安全和资产分发权利仍为 OPEN。
