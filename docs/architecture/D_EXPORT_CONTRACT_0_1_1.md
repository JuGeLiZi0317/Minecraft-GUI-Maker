# D 导出合同 0.1.1：增加放大参考图

2026-10-27。此修订针对设计区逻辑像素较小时 PNG 不易阅读的问题。原 [0.1.0 冻结合同](D_EXPORT_CONTRACT.md)继续作为历史基准；本文件明确列出变更。原始 Schema、权威 JSON、1× 设计区 PNG 语义与已提交单快照输入边界保持不变。

导出批次标识和 manifest 版本升级为 0.1.1。一个批次增加 `<batch>.reference.png`，共六个独立下载文件；manifest 列出其他五个文件的精确字节数和 SHA-256，不对自身做递归摘要。六个文件全部成功后才发布，任一步失败均不发布部分结果。

`reference.png` 也是从同一不可变文档快照直接绘制的设计区近似参考图，**不是截图放大，也不是新的权威设计数据**。尽量使用整数4×倍率，每轴最多8192像素且总像素最多16,777,216；超出限制时自动选择不超过4的最大可用整数倍率。若只能使用1×，直接复用透明的原图字节，在下载标签和manifest明确标示“无法放大”，不能宣称已提供高分辨率。例：320×180生成1280×720的4×参考图，4096×4096只能生成1×。

放大参考图通过 Canvas2D 在放大后的画布上按相同逻辑坐标重绘，并将字体按画布变换放大；它没有选择框或编辑辅助线。为便于在白色或透明背景的查看器阅读，2×以上的参考图使用 `#1c2634` 深色衬底：该衬底仅属于参考图，不表示设计 JSON 的背景、不代表游戏窗口背景。1×原设计图继续透明。文字与颜色仍是浏览器近似，游戏内视觉、字体和语言仍未验证；放大也不能保证任何特定 AI 模型或视觉处理管线能准确识别。

图片 tEXt 元数据和 manifest `enlargedReferenceImage` 记录完整批次 reference、图像宽高、逻辑设计尺寸、倍率、坐标原点与背景。1图像像素对应1/倍率个GUI逻辑单位；坐标和尺寸以权威 JSON 为准。保留原 `designImage` 的 `pixelRatio=1` 与透明背景。设计超过原有PNG操作上限时仍拒绝整批，不缩小原图或修改设计。
