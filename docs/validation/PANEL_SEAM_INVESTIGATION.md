# 九宫格接缝调查：PENDING

2026-10-28。Chrome 156.0.8078.48；Playwright 1.56.1，1440×1000 CSS px，模拟 DPR 1/2。用户截图中的阶梯黑边属于原图；仅调查内部细线。用户素材是发射器纹理衍生图，不是游戏自带的 Panel Widget。

## 证据和原因

`src/render/panelTexture.ts` 的素材经 SHA-256 和尺寸校验，mcmeta 指定 16×16、四边各 4；32×旧素材先整体最近邻缩成16×16。源图16×16含18个完全透明像素，不能把透明角落视为错误。九块目标区间以 0、4、width−4、width 和相应高度计算，整数逻辑坐标严格相接；各块边、中心使用裁剪源矩形创建平铺图案，角为 drawImage。源矩形在图内。没有独立的切片描边；网格和选中框是后绘制、可独立关闭的辅助层，复现中未启用。

原网页 Konva Shape 在同一个带 zoom、pan 和设备像素倍率的变换下逐块调用 drawImage/fillRect；各块启用 `imageSmoothingEnabled=false`，但它不禁止变换后图形边界的覆盖率抗锯齿及与深色背景的混合。合成时这些独立边界能暴露深色底，造成暗线。此判断由相同素材和逻辑尺寸的 Canvas 像素对照支持；并不能仅凭截图证明截图的具体设备变换参数。

隔离复现：320×180，背景 RGB(28,38,52)，2×，原点 (20.37,20.37) 设备像素；源与目标语义相同，逐块绘制对比在整数逻辑画布先合成后单次最近邻绘制。竖边界 x≈28.37 附近存在338个较暗像素，其中 (28,25) 原结果 RGB(202,204,208)，整体合成为 RGB(255,255,255)；横边界 y≈28.37 附近639个较暗像素，(28,27) 原 RGB(159,161,164)，整体合成为 RGB(198,198,198)。数字是边界附近两像素带内的计数，不等同于一像素线的精确长度。交叉位置可能重复计数。

首轮未修复测试使用 37×29、320×180，zoom 0.5/1/2/1.37，pan 0/0.37，模拟 DPR 1/2：在分数落点出现像素差异，例如320×180、DPR1、2×、pan 0.37有2966个不同像素，其中1981个更暗；对齐的2×、pan 0为0。差异包含内部及外部边缘，不全部归因于内部接缝。[原始记录](panel-seams-before-results.json) 为预期失败的基线。

## 修复与验证

`src/render/panelTexture.ts` 为预览增加按图像和尺寸缓存的一张逻辑像素离屏图，复用原九宫格算法；`src/canvas/Canvas.tsx` 将其作为整体以最近邻绘制。设计模式和 GUI Scale 预览共用 Shape；不改变源素材、切片语义、逻辑坐标、领域模型或导出代码。尺寸变化替换旧缓存，每个已加载源图最多持有一个；理论像素内存上限每张约64 MiB，不含浏览器开销。两种旧/新纹理同时加载时最多两张。Canvas 像素一致性与缓存替换有测试；实际浏览器内存回收未测。

修复后相同隔离矩阵相对逻辑图整体绘制的 RGBA 差异为0；实际 Konva 画布在 zoom 0.5/1/2、pan 0/0.37及 GUI Scale 预览中逐像素检查四条内部边界附近，DPR1/2均通过。现有 Panel 专项覆盖源角、边、中心及导出。像素比较是精确相等（容差0），没有引入遮线或模糊。此验证不等于所有缩放、浏览器或物理屏幕视觉验收。[修复后专项结果](panel-seams-after-results.json) 包含像素和采样附件。

命令：`npm.cmd run typecheck`、`npm.cmd run build`、`npm.cmd test` 均通过（Vitest 66/66；构建有既有大包提示）；`$env:GUI_BROWSER_CHANNEL='chrome'; npx.cmd playwright test tests/panel-seams.spec.ts tests/supplied-panel.spec.ts tests/panel-background.spec.ts tests/screen-scale.spec.ts --trace off` 通过30/30。随后增加像素诊断与缓存检查，`npx.cmd playwright test tests/panel-seams.spec.ts --trace off` 通过8/8。初始复现专项按预期2项失败，记录保留。未执行完整 Playwright 套件。

## 性能与待办

隔离 Canvas 微基准，320×180底板、2×、每帧附加300个简单 fillRect，单线程各5组×100次，Chrome 无头；首次含预热，计时只覆盖 JS 提交绘制命令，不测 GPU 完成或真实拖动帧率。DPR1旧路径每100次约 188～360 ms，新缓存路径约 4～111 ms；DPR2配置此微基准使用相同固定设备画布尺寸，因此不是物理 DPR 性能比较。该采样不构成设备性能保证。

**PENDING**：设计区单轴超过8192或面积超过16,777,216像素时为避免无限分配而回退逐块绘制，分数落点仍可能出现接缝。尚未验证这种超大尺寸的无缝渲染或浏览器资源限制；真实游戏 Scale 的视觉一致性、物理 DPR、其他浏览器及用户截图相同设备参数的人工复核也仍待验证。已测试范围内的像素结果不能关闭这些问题。
