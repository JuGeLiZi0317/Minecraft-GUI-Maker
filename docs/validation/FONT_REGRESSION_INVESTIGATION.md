样本是居中的 StringWidget（200×24），包含英文、数字、标点与中文，直接记录边界；宽度和截断区域保持不变。高分辨率画布重新光栅化文字，而参考 PNG 是 1× 后放大，两者不是同一设备分辨率。DPR 2 / zoom 1 的一设备像素垂直平移可减少 172 个不匹配像素，剩余 458 个仍包括笔画和阈值差异；该统计不能精确区分抗锯齿、字形栅格或基线差异。高倍率的纵向边界偏移和裁切边缘应继续调查，不能据此声称纯抗锯齿或扩大容差。先前 258/200 测试使用另一组三组件与不同下采样方法，不能与本表数字直接相加。原失败截图保留为 `prior-dpr2-failure.png`。

历史两份完整结果均为 103 通过、49 失败、0 跳过，但执行于不同代码与并发配置。逐项检查显示大部分超时等待被选中组件时隐藏的屏幕工具，属于旧定位器与布局不一致；性能采样在 6 秒内未结束，不能判为性能缺陷；DPR 2 字体断言为真实测试失败，原因仍未完全归因。部分导出、资源及持久化超时需在适配定位器后重测，不能仅凭超时排除产品问题。新增文字状态的 role 曾干扰旧定位器，先前已改为 aria-live。

Windows 的 `CreateProcessWithLogonW failed: 1909` 当时同时阻止新命令和 Node 结果读取进程启动；第二次测试进程本身先退出 1，不能认定网站本身因此失败。本次未改账户或安全设置，命令执行能力已自行恢复，但无法确认底层触发原因。当前 typecheck、build、86 项 Vitest 均退出 0；Vite build 仍提示 chunk 超 500 kB。

此次修改仅适配部分旧测试的撤销快捷键与视图设置流程，并增加诊断；没有更改产品源码或 Schema。DPR1 的 interaction-review 7 项通过；合并 editor 的针对性试跑为 10 通过、4 失败，其中 3 项因测试点击画布位置被侧栏按钮遮挡，现已调整测试坐标，性能项被 10 秒截断并已改为 60 秒预算。这两项测试修正尚未取得单独的最终通过证明。
